# kb-compile

## 职责

读取 raw/.extracted/ 或 raw/ 文件，LLM 提取实体，生成 wiki 页面。支持迭代遗漏处理。

## 意图识别

| 用户意图 | 执行方式 |
|---------|---------|
| "compile" | 单轮提取 + 遗漏清单输出 |
| "完整 compile" | 迭代提取（最多 3 轮） |
| "补充 compile" | 读取 raw-registry.md 剩余遗漏 → 针对性提取 |
| "重新 compile" | 清空状态 → 执行完整 compile |

触发词示例：
- 默认："compile raw 文件"、"开始编译"
- 完整："完整 compile"、"穷尽提取"、"确保不遗漏"
- 补充："补充 compile"、"继续提取遗漏"
- 重新："重新 compile"、"重新编译 xxx 文件"

## 执行流程

1. **读取 raw-registry.md**：筛选需编译文件（预处理状态 != 未处理 且 编译状态 != 已编译/已引用）
2. **读取文件内容**：
   - 产物路径 != `-`：调用 `read_file.py` 读取产物路径对应文件
   - 产物路径 == `-`：调用 `read_file.py` 读取 raw 文件本身
3. **LLM 提取（根据意图）**：

   **默认模式**：
   - 单轮提取实体（人物、地点、事件、制度、官职、思想）
   - 输出提取清单 + 遗漏清单
   - 参考 templates 约束 wiki 页面格式（不约束提取范围）
   - 穷尽提取原则：不遗漏次要人物、地点、事件、官职

   **完整模式**：
   - 第一轮：穷尽提取 → 输出提取清单 + 遗漏清单 A
   - 第二轮（遗漏清单 A 非空）：针对性补充 → 输出遗漏清单 B
   - 第三轮（遗漏清单 B 非空）：针对性补充 → 输出遗漏清单 C
   - 上限：3 轮
   - 收敛条件：连续两轮无新遗漏
   - 每轮检查：是否有遗漏的次要人物、地点、事件、官职、年号等

   **补充模式**：
   - 读取 raw-registry.md 的"剩余遗漏"字段
   - 针对遗漏实体提取详情
   - 执行迭代检查新遗漏（包括次要人物、地点、事件、官职、年号）

   **重新模式**：
   - 清空该文件的编译状态
   - 执行完整模式（穷尽提取）
4. **LLM wiki 生成**：
   - 检查 wiki/ 是否已有对应实体文档
   - 无：根据 templates 创建新文档
   - 有：阅读现有内容，合并新信息（增量更新）
   - wiki 文档 source 字段：`- source: [[raw/path/to/source.md]]`
5. **更新 index.md**（根目录）：添加新页面索引到对应 section
6. **更新 log.md**（根目录）：追加 compile 操作记录
7. **更新 raw-registry.md**（根目录）：调用 `update_registry.py`
   - 编译状态：已编译 / 部分编译
   - 剩余遗漏：空 / 实体1, 实体2, ...（逗号分隔）
   - 最近处理日期：当前日期

## 增量更新逻辑

| 场景 | LLM 处理方式 |
|------|-------------|
| 信息补充 | 追加新字段或补充现有字段内容 |
| 信息冲突 | 判断是否同一信息的不同表述，或保留冲突注释 |
| 关系去重 | 判断两个关系是否重复，合并 |
| 结构调整 | 根据信息量调整页面结构 |

## templates 说明

| template | 用途 |
|----------|------|
| person-template.md | 历史人物页面格式（约束输出格式，不约束提取范围） |
| place-template.md | 历史地点页面格式（约束输出格式，不约束提取范围） |
| event-template.md | 历史事件页面格式（约束输出格式，不约束提取范围） |
| institution-template.md | 制度页面格式（约束输出格式，不约束提取范围） |
| official-template.md | 官职页面格式（约束输出格式，不约束提取范围） |
| thought-template.md | 思想页面格式（约束输出格式，不约束提取范围） |

**注意**：templates 用于约束 wiki 页面的结构格式，不约束提取范围。LLM 应灵活提取，不受模板类型限制。

## 遗漏清单检查指导

在每轮提取后，检查以下类型的遗漏：

| 检查项 | 示例 |
|--------|------|
| 次要人物 | 文中提及但未提取的人物（如樊哙、项伯） |
| 古今地名 | 古地名及对应今地名（如垓下→安徽灵璧） |
| 补充事件 | 文中提及的事件（如潍水之战、白登之围） |
| 官职爵位 | 人物的官职、爵位（如亭长、淮阴侯） |
| 年号纪年 | 文中出现的年号、纪年（如公元前206年） |
| 朝代政权 | 文中提及的朝代、政权（如秦朝、西楚） |

## scripts 使用说明

| script | 用途 | 调用时机 | 依赖类型 |
|--------|------|---------|---------|
| read_file.py | 根据路径读取文件 | 步骤 2：读取待编译文件内容 | 必须 |
| update_registry.py | 更新 raw-registry.md | 步骤 6：更新编译状态 | 必须 |

依赖类型说明：
- 必须：流程步骤明确依赖该 script

## 输出摘要

完成后输出：
1. **处理结果**：生成 X 个 wiki 文档（Y 人物，Z 地点，W 事件，U 制度，V 官职，T 思想）
2. **迭代信息**（完整/补充模式）：
   - 迭代次数：N 轮
   - 收敛状态：已收敛 / 未收敛（达到上限）
3. **剩余遗漏**（如有）：
   - 实体列表：A, B, C
   - 提示：可执行"补充 compile"继续提取
4. **下一步提示**：
   - 可运行 kb-lint 检查 wiki 格式
   - 如有剩余遗漏，可执行"补充 compile"

示例（已收敛）：
```
处理结果：生成 15 个 wiki 文档（5 人物，3 地点，2 事件，2 制度，2 官职，1 思想）
迭代信息：迭代 3 轮，已收敛
剩余遗漏：空
下一步提示：可运行 kb-lint 检查 wiki 格式
```

示例（未收敛）：
```
处理结果：生成 20 个 wiki 文档（8 人物，4 地点，3 事件，2 制度，2 官职，1 思想）
迭代信息：迭代 3 轮，未收敛（达到上限）
剩余遗漏：范增, 龙且, 钟离昧
下一步提示：可执行"补充 compile"补充遗漏实体
```
