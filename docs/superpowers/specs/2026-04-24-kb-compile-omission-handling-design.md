# kb-compile 遗漏处理设计

> 本文档定义 kb-compile 的遗漏实体处理机制，解决"大文件提取不完整"问题。

---

## 1. 问题定义

### 1.1 现状

kb-compile 当前流程：
- LLM 单次调用提取实体
- 无穷尽检查机制
- 用户不知道遗漏了什么

**痛点**：当 raw 文件较大时，LLM 只提取它认为"重要"的实体，无法穷尽所有实体。

### 1.2 问题本质

| 类别 | 说明 | LLM 能识别 |
|------|------|-----------|
| 已提取 | LLM 提取的实体 | ✓ |
| 已知遗漏 | LLM 注意到但未提取的实体 | ✓ |
| 未知遗漏 | LLM 从未注意到的实体 | ✗ |

**根本矛盾**：遗漏清单只能包含 LLM "意识到但没提取"的内容，无法包含 LLM "完全没意识到"的内容（Unknown Unknowns）。

---

## 2. 设计原则

| 原则 | 理由 |
|------|------|
| 职责清晰 | compile 负责 raw → wiki，不引入其他 skill 介入 |
| 最小改动 | 仅修改 SKILL.md + raw-registry.md 字段 |
| 迭代收敛 | 处理 unknown unknowns，设置上限避免无限循环 |
| 持久化最小 | 仅存储遗漏实体名称，不存储详情 |
| 用户可控 | 意图识别明确，用户选择 compile 模式 |

---

## 3. 解决方案

### 3.1 核心机制：迭代收敛

```
第一轮：提取实体 → 输出遗漏清单 A
第二轮：针对性补充 → 输出遗漏清单 B（新发现的遗漏）
第三轮：针对性补充 → 输出遗漏清单 C（新发现的遗漏）
收敛判断：连续两轮无新遗漏 → 停止
上限：最多 3 轮
```

**原理**：
- 每轮提取后，LLM 重新审视文档
- 检查是否有"新发现的遗漏"
- 当无新遗漏 → 收敛

### 3.2 遗漏清单本质

- 遗漏清单不是独立文件
- 是同一"遗漏清单"概念在迭代过程中的状态
- 每轮遗漏清单只包含"本轮新发现"的遗漏
- 最终遗漏清单持久化到 raw-registry.md

## 4. 改动详情

### 4.1 kb-compile SKILL.md 改动

#### 4.1.1 新增意图识别

```markdown
## 意图识别

| 用户意图 | 执行方式 |
|---------|---------|
| "compile" | 单轮提取 + 遗漏清单输出 |
| "完整 compile" | 迭代提取（最多 3 轮） |
| "补充 compile" | 读取 raw-registry.md 剩余遗漏 → 针对性提取 |
| "重新 compile" | 清空状态 → 执行完整 compile |
```

#### 4.1.2 流程改进

**步骤 3 改为迭代提取**：

```markdown
## 执行流程

1. 读取 raw-registry.md
2. 根据意图筛选文件：
   - 默认：筛选"已处理但未编译"文件
   - 完整：筛选"已处理但未编译"文件 + 执行迭代
   - 补充：读取指定文件的"剩余遗漏"字段
   - 重新：忽略状态，重新执行
3. 读取文件内容
4. **LLM 提取（根据意图）**：
   
   **默认模式**：
   - 单轮提取实体
   - 输出提取清单 + 遗漏清单
   
   **完整模式**：
   - 第一轮：提取实体 → 输出提取清单 + 遗漏清单 A
   - 第二轮（遗漏清单 A 非空）：针对性补充 → 输出遗漏清单 B
   - 第三轮（遗漏清单 B 非空）：针对性补充 → 输出遗漏清单 C
   - 上限：3 轮
   - 收敛条件：连续两轮无新遗漏
   
   **补充模式**：
   - 读取 raw-registry.md 的"剩余遗漏"字段
   - 针对遗漏实体提取详情
   - 执行迭代检查新遗漏
   
   **重新模式**：
   - 清空该文件的编译状态
   - 执行完整模式
   
5. 生成 wiki 页面
6. 更新 index.md
7. 更新 raw-registry.md：
   - 编译状态：已编译 / 部分编译
   - 剩余遗漏：空 / 实体1, 实体2, ...（逗号分隔）
8. 输出摘要：
   - 处理结果：生成 X 个 wiki 文档
   - 剩余遗漏：Y 个实体（如有）
   - 下一步：可执行"补充 compile"或 kb-lint
```

#### 4.1.3 输出摘要改进

```markdown
## 输出摘要

完成后输出：
1. **处理结果**：生成 X 个 wiki 文档（Y 实体，Z 概念）
2. **迭代信息**（完整模式）：
   - 迭代次数：N 轮
   - 收敛状态：已收敛 / 未收敛（达到上限）
3. **剩余遗漏**（如有）：
   - 实体列表：A, B, C（可执行"补充 compile"）
4. **下一步提示**：
   - 可运行 kb-lint 检查 wiki 格式
   - 如有剩余遗漏，可执行"补充 compile"

示例：
```
处理结果：生成 8 个 wiki 文档（5 实体，3 概念）
迭代信息：迭代 3 轮，已收敛
剩余遗漏：空
下一步提示：可运行 kb-lint 检查 wiki 格式
```

示例（未收敛）：
```
处理结果：生成 12 个 wiki 文档（8 实体，4 概念）
迭代信息：迭代 3 轮，未收敛（达到上限）
剩余遗漏：范增, 龙且, 钟离昧
下一步提示：可执行"补充 compile"补充遗漏实体
```
```

### 4.2 raw-registry.md 改动

#### 4.2.1 新增字段

| 字段名 | 类型 | 说明 |
|--------|------|------|
| 剩余遗漏 | string | 剩余遗漏实体名称，逗号分隔，或"空" |

**示例**：

```markdown
| 文件路径 | 类型 | 预处理状态 | 产物路径 | 编译状态 | 最近处理日期 | 剩余遗漏 |
|----------|------|-----------|---------|---------|------------|---------|
| raw/史记/高祖本纪.md | markdown | 已处理 | - | 已编译 | 2026-04-24 | 空 |
| raw/史记/项羽本纪.md | markdown | 已处理 | - | 部分编译 | 2026-04-24 | 范增, 龙且, 钟离昧 |
| raw/汉书/高帝纪.md | pdf | 已处理 | raw/.extracted/汉书/高帝纪.md | 未编译 | - | - |
```

#### 4.2.2 字段约定

- `空`：已收敛，无遗漏
- `实体1, 实体2, ...`：剩余遗漏实体清单（逗号分隔）
- `-`：未编译，字段不适用

### 4.3 不改动项

| 项目 | 理由 |
|------|------|
| kb-query SKILL.md | 不参与 entity extraction，职责保持搜索 wiki |
| kb-archive SKILL.md | 不参与 entity extraction，职责保持 report → wiki |
| CLI 命令 | 通过意图识别触发，不新增 CLI 命令 |
| 独立遗漏报告文件 | 存储冗余，raw-registry.md 已足够 |
| scripts | 不新增 scripts，仅修改 SKILL.md 文本 |

## 5. 流程图

### 5.1 完整模式流程

```
用户："完整 compile raw 文件"

agent：
  ↓
  读取 raw-registry.md → 筛选"已处理但未编译"文件
  ↓
  读取 raw 文件内容
  ↓
  第一轮 LLM 提取：
    提取清单：刘邦, 萧何
    遗漏清单：韩信, 彭越, 鸿门宴
  ↓
  第二轮 LLM 提取：
    补充提取：韩信, 彭越, 鸿门宴
    遗漏清单：陈平
  ↓
  第三轮 LLM 提取：
    补充提取：陈平
    遗漏清单：空
  ↓
  收敛判断：遗漏清单为空 → 已收敛
  ↓
  生成 wiki 页面（6 个实体）
  ↓
  更新 index.md
  ↓
  更新 raw-registry.md：
    编译状态：已编译
    剩余遗漏：空
  ↓
  输出摘要：
    "生成 6 个 wiki 文档
    迭代 3 轮，已收敛
    下一步：kb-lint"
```

### 5.2 补充模式流程

```
用户："补充 compile raw/项羽本纪.md"

agent：
  ↓
  读取 raw-registry.md → 剩余遗漏：范增, 龙且, 钟离昧
  ↓
  读取 raw 文件内容
  ↓
  针对性提取：
    范增 → 详情提取
    龙且 → 详情提取
    钟离昧 → 详情提取
  ↓
  第二轮检查（如有新遗漏）：
    新遗漏清单：项伯
  ↓
  第三轮检查：
    新遗漏清单：空
  ↓
  更新 wiki 页面
  ↓
  更新 raw-registry.md：
    剩余遗漏：空 或 新遗漏内容
  ↓
  输出摘要
```

## 6. 边界情况处理

| 场景 | 处理方式 |
|------|---------|
| 迭代未收敛（3 轮后仍有遗漏） | 标记"部分编译"，用户可选择继续"补充 compile" |
| 遗漏实体同名不同义 | 用户可在"补充 compile"时澄清 |
| 用户忘记意图触发词 | SKILL.md 示例提示，agent 可识别模糊意图 |
| raw 文件极小（无遗漏） | 单轮即可收敛，输出"空" |
| raw 文件极大（>100KB） | 建议用户分块预处理，或接受迭代上限 |

---

## 7. 风险评估

| 风险 | 影响 | 处理 |
|------|------|------|
| 迭代成本增加 | API 调用增加（最多 3 轮） | 用户可选择"默认模式"（单轮） |
| 遗漏清单仍不完整 | Unknown unknowns 无法完全解决 | 承认局限，渐进补充机制兜底 |
| 持久化冲突 | 同名实体歧义 | 用户澄清或接受 |
